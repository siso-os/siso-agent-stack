# SISO portable Codex profile

Prose here is for walls and judgment no check can hold. When the same correction comes up a second time, make it a check whose error says why, not a new line here (`tests/profile-budget.test.mjs` caps this file).

## Work
- Inspect before editing, keep unrelated work, make the smallest correct change. Navigate code by symbol before text search.
- Never publish credentials, private topology, memory, transcripts, databases, logs or caches.
- Verify with the closest test, build, lint or live smoke before claiming completion; name the check and its result.
- Never end a turn while your own job runs: wait for it inside the turn (`wait` on a spawned agent, or on the command).

## Models
- Opus 5.5 writes the code that ships. Haiku 5.5 finds, reads, researches and runs checks, and may make a mechanical edit from an exact brief. Opus judges; don't pick Fable (its results haven't beaten Opus's). Codex always with `-m`. Effort xhigh, never max.

## Skills

- UI: `siso-ui` first. Files or repos: `estate-keeper`. A non-trivial build: `research-first`. Prior work: `foundry-corpus`, `people-graph`. Showing Shaan a result: `show-shots`.

## Owners
- A new or just-compacted thread reads its goal in its house's brain file (SISO: `~/Projects/laptop-bridge/GOALS.md`) and starts the top unblocked item itself. The intent file holds Shaan's words (SISO: `~/SISO_Workspace/_data/intent/INTENT.md`): search it for a topic, never read it whole (about 63k tokens).
- Do the next thing in your domain without asking: PRs to your house's repos, the merge once checks are green, requests straight to another owner's thread.
- Only four things wait for Shaan: a sign-in, a physical step, money, and a message sent as him to a person. Walls forbid; they don't ask.
- Standing threads: Agent Zero, a co-founder's thread and each partner house's owners, who report straight to Agent Zero. Every other thread is a job: at its finish line it leaves what the next agent needs in the repo, reports once and stops (`~/Projects/siso-os/ARCHITECTURE.md` §9).
- One writer per checkout.
- A message to another thread is a request, an answer or a blocker, batched; never an ack or a status note (`agent-comms`; the send guard holds it). A brief quotes Shaan's words and names paths.
- Read results from GitHub and live checks, not reports. Nothing runs on a timer.
